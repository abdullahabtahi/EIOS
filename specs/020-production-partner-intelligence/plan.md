1. Implementing a synchronized Dual Scatter-Triage Grid supporting 50+ partner profiles with sub-50ms search and sort.

5. Surfacing closed-loop Experience Library empirical win rates and live shadow model Brier calibration metrics ($< 0.10$).

## Phase 0: Research & Key Technical Decisions

### Decision 1: Master-Detail Synchronization Pattern (TanStack Grid + SVG Canvas)
- **Context**: Partner Managers need to navigate between a macroscopic scatter plot and a microscopic tabular grid.
- **Decision**: Implement `PartnerTriageGrid` synchronized with `churn-radar-scatter.tsx` via `cockpit-context.tsx`. Selecting an entity in either component immediately updates the active focal state across both views in $< 16\text{ms}$ (60 FPS).
- **Alternatives Considered**: Tabbed view (forces context switching); Floating popover (obscures canvas).

### Decision 2: Historical Drift Representation (Dotted Bezier Trails with Chevrons)
- **Context**: Churn is a progressive time-series decay.
- **Decision**: Pre-calculate $T-30\text{d}$ and $T-14\text{d}$ historical coordinates in the backend domain service. Render them as subtle dotted trails with directional chevrons and a hover tooltip showing acceleration of decay.
- **Alternatives Considered**: Full multi-line timeline chart (causes cognitive clutter on the scatter canvas).

### Decision 3: Debounced Asynchronous What-If Causal Evaluation
- **Context**: Slider interactions must feel fluid while avoiding spamming the backend Python inference engine.
- **Decision**: Update the client-side simulated coordinate optimistically during slider drag (`onInput`), and dispatch a debounced request ($250\text{ms}$) on slider release (`onPointerUp`) to `POST /api/v1/churn/partner/{id}/what-if` to retrieve the definitive DoWhy causal verdict and $p$-value.
